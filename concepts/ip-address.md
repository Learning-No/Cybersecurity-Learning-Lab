<article class="learning-page"><a class="back-link" href="{{ '/concepts/' | relative_url }}">← Concepts library</a><p class="eyebrow">CONCEPT 01 / NETWORKING</p><h1>IP address: <em>where traffic is directed</em></h1><p class="lead">An IP address identifies a network interface at the IP layer so packets can be addressed and routed. A device can have multiple interfaces and multiple addresses.</p>
<div class="definition-row"><div><h2>In plain language</h2><p>Think of an IP address as a delivery destination for network traffic. It does not, by itself, identify a person, prove ownership, or show that a system is vulnerable.</p></div><div class="concept-facts"><p><b>IPv4</b><span>Example documentation address: 192.0.2.10</span></p><p><b>IPv6</b><span>Longer address format, e.g. 2001:db8::10 (documentation range)</span></p><p><b>Private vs public</b><span>Private addresses are used within private networks; public addresses are globally routable in normal circumstances.</span></p></div></div>
<h2>Diagram: how a browser reaches a website</h2><div class="diagram-panel"><div class="flow-diagram"><div class="flow-node">Your device<small>Local interface IP</small></div><div class="flow-arrow">→</div><div class="flow-node">Router / gateway<small>Forwards traffic</small></div><div class="flow-arrow">→</div><div class="flow-node">DNS resolver<small>Finds a record</small></div><div class="flow-arrow">→</div><div class="flow-node">Web server<small>Destination IP</small></div></div><p class="diagram-caption">Simplified illustration: DNS resolution and packet routing are related but separate operations; real networks may use caches, proxies, CDNs, and many routers.</p></div>
<h2>How to find an IP address — safe workflow</h2><ol class="process-list"><li><b>Define which IP you mean.</b><p>Local interface address, public egress address, or the address returned for a domain are different questions.</p></li><li><b>Inspect your own device.</b><p>Use operating-system network settings or the open-source <code>ip</code> utility on Linux.</p></li><li><b>For a domain, query DNS.</b><p>Use <code>dig</code> or <code>host</code> to inspect records for a domain you are permitted to look up.</p></li><li><b>Interpret the result.</b><p>DNS may return several addresses or CDN endpoints. The result can change over time and is not proof of who operates a host.</p></li><li><b>Record context.</b><p>Note the command, timestamp, resolver, and answer. Redact personal/public IPs before posting notes.</p></li></ol>
<h2>Open-source tools</h2><div class="mini-tool-grid"><article><h3><code>ip</code> (iproute2)</h3><p>Shows and manages Linux network interfaces, addresses, and routes.</p><pre><code>ip address show
ip route show</code></pre><p>Read-only inspection examples; the commands above do not change network settings.</p></article><article><h3><code>dig</code></h3><p>Queries DNS records. Commonly packaged with BIND utilities.</p><pre><code>dig example.com A
dig example.com AAAA</code></pre><p>Use a domain as an example of DNS resolution; results can vary by resolver and time.</p></article><article><h3><code>host</code></h3><p>A small DNS lookup utility, often distributed with BIND utilities.</p><pre><code>host example.com</code></pre></article><article><h3><code>Wireshark</code></h3><p>Open-source packet analyzer for learning how DNS and IP packets appear on your own device or lab.</p><p>Capture only traffic you are authorized to inspect; packet captures can contain sensitive data.</p></article></div>
<h2>Common misunderstandings</h2><ul><li>A public IP may represent a router, proxy, VPN, CDN, or shared hosting—not one individual device.</li><li>A domain's DNS answer is not necessarily the origin server.</li><li>An IP address alone does not prove a service is running or that a vulnerability exists.</li></ul>
<h2>Practice task</h2><p>On your own computer, record the local interface address and default gateway using system settings or <code>ip address show</code> and <code>ip route show</code> on Linux. Separately, run a DNS lookup for <code>example.com</code>. Draw the two paths and explain why they answer different questions.</p>
