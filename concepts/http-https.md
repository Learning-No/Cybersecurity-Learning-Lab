<article class="learning-page"><a class="back-link" href="{{ '/concepts/' | relative_url }}">← Concepts library</a><p class="eyebrow">CONCEPT 05 / WEB</p><h1>HTTP & HTTPS: <em>the web conversation</em></h1><p class="lead">HTTP defines how clients and servers exchange requests and responses. HTTPS is HTTP protected by TLS, helping protect confidentiality and integrity in transit and authenticate the server when certificate checks succeed.</p>

This drawing shows a common HTTPS-over-TCP flow.</p></div>
<h2>Parts of an HTTP exchange</h2><div class="definition-list"><details><summary>Method and path</summary><p>GET often retrieves data; POST often submits data. Actual behavior depends on the application and server implementation.</p></details><details><summary>Headers</summary><p>Metadata such as content type, cache directives, cookies, and security policies.</p></details><details><summary>Status code</summary><p>2xx usually indicates success, 3xx redirection, 4xx a client/request issue, and 5xx a server-side failure.</p></details><details><summary>Body</summary><p>Optional request or response content, such as HTML, JSON, form data, or an uploaded file.</p></details><details><summary>Cookies and sessions</summary><p>Cookies are values stored and sent by the browser according to their attributes; server-side sessions often associate a browser with state. Treat session tokens as secrets.</p></details></div>
<h2>Safe inspection workflow</h2><ol class="process-list"><li>Open a local demo app or explicitly authorized training site.</li><li>Open browser Developer Tools → Network and reload the page.</li><li>Select a request and note method, path, status, content type, and timing.</li><li>Compare expected behavior with the observed response using dummy data.</li><li>Do not copy real credentials, cookies, authorization headers, or personal data into notes.</li></ol>
<h2>Open-source tools</h2><p><b>Firefox Developer Tools</b> are built into Firefox. <b>curl</b> is an open-source command-line transfer tool useful for learning request/response behavior on systems you are allowed to access.</p><pre><code>curl -I https://example.com
curl -sS -o /dev/null -w "%{http_code}\n" https://example.com</code></pre><p>These examples make ordinary requests to a documentation/example domain; do not add authentication secrets to shared commands.</p>
